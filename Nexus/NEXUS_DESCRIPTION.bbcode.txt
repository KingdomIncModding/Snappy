[b]Snappy - 1.0.0[/b]
Place nodes, pipe bends and decorations with three additional snap positions between each original grid interval.

[b]Features[/b]
[list]
[*]Four steps per original grid interval: 0, 16, 32, 48, 64.
[*]Finer snapping on both axes for node placement/dragging, purchase and copy previews, pipe bends, decorations and container resizing.
[*]Preserves the original pipe alignment and label offsets.
[*]Hold Ctrl to use the game's usual free placement.
[/list]

[b]Requirements[/b]
Kingdom Inc (Unity Mono) with BepInEx 5 and its bundled Harmony. Tested with Release v1.0.12, Unity 6000.3.27f2 and BepInEx 5.4.23.6. No other plugin is required.

[b]Installation[/b]
1. Install BepInEx 5 for the game if needed.
2. Close Kingdom Inc.
3. Extract the player ZIP into the game folder. The plugin belongs at BepInEx/plugins/Snappy/Snappy.dll.
4. Launch the game and move a node. Snappy is active automatically; no configuration or hotkey is needed.

[b]Updating[/b]
Close the game and replace Snappy.dll, then launch again. There are no additional save fields or migration steps.

[b]Compatibility and known issues[/b]
The visible background grid keeps its original spacing. Extra snap positions lie between its lines. Node sizes, port counts and minimum container size are unchanged. Existing layouts are not repositioned.
353 isolated runtime checks passed, and the same 353 passed with the nine installed companion plugins loaded, including Port Layouts 1.0.1 and Sharable Blueprints 0.5.2. This checks Snappy's native placement behavior; it does not retest every companion feature or shared blueprint format.
Another plugin replacing WorldFlowManager.ClampToGrid may conflict. Manual installation is supported; Vortex is untested.

[b]Removal[/b]
Close the game and delete BepInEx/plugins/Snappy. Existing fine positions survive native save loading without Snappy; further movement uses the game's normal grid.

[b]Changes in 1.0.0[/b]
Initial release with quarter-grid snapping on both axes.
